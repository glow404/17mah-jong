# 对局历史、事件日志与回放

## 事件模型

联机牌局由带有单调递增 `sequence`、牌局 `stateVersion`、时间戳、座位、类型和类型化载荷的事件表示。当前事件包括建局、旧牌局状态检查点、玩家入座、选牌、启动回合时限、舍牌、放弃荣和、荣和、流局和判负。`game_events` 的复合主键保证同一牌局内序号唯一，数据库触发器拒绝更新既有事件；删除账号时允许外键级联删除其相关历史，以支持隐私删除。

每次联机操作先按房间版本做 compare-and-set，再在同一 D1 批次中追加事件并更新历史摘要。并发操作失败时不会留下悬空事件。一个操作可能产生多个事件（例如第 17 巡舍牌后紧接流局），它们共享同一状态版本但使用不同序号。事件序号必须连续；除这种舍牌后的终局事件外，状态版本必须逐事件递增。

电脑对战沿用同一事件契约和纯函数回放器，但历史只保存在当前浏览器的 `localStorage`，最多保留最近 50 局，不上传或跨设备同步。清理该站点的浏览器数据会一并清除这些本地牌谱。

## 重建和完整性检查

`lib/history/replay.ts` 是确定性的状态归约器：给定建局事件或迁移检查点，以及按序事件，它会返回每个事件之后不可变的状态快照。回放期间会校验事件序号、版本连续性、牌池唯一性、实体牌范围、选牌归属、当前行动座位、舍牌余量、荣和条件和流局条件。结束事件后的额外操作、伪造舍牌、非法快照或无法重建的记录都会被拒绝。

旧版本已有的房间由数据库迁移转换成一个不含房间凭证或账号字段的 `match.restored` 检查点。之后的事件仍从该状态版本继续；新牌局则从 `match.created` 开始完整记录。

## 访问控制、隐私和导出

- 历史列表只返回已完成且当前账号参与的牌局摘要。请求单局回放时，服务端再次检查参与者身份；其他账号得到 404，不得据猜测的牌局 ID 查看记录。
- 电脑对战历史留在玩家的浏览器。联机历史存入 D1，并随参与者账号删除而级联清除；目前没有自动到期策略，用户可通过仓库公开的安全/隐私联系渠道申请人工删除。
- 牌谱 JSON 采用显式字段白名单。不会导出邮箱、账号 ID、会话令牌、房间码、房间凭证、Cookie、presence 或内部数据库字段。
- 为了让离线回放可以重建完整对局，导出仍包含牌池、双方已选手牌、舍牌、宝牌指示牌和结算明细。这些内容会揭示对局中曾隐藏的信息；请只与愿意分享完整牌谱的人分享。
- JSON 导出含格式标识 `17mah-jong-replay` 和 `schemaVersion`，后续格式变更应提升版本并保留迁移或兼容策略。

## UI 行为

历史列表将浏览器本地电脑对战与账号联机对战合并，按完成时间倒序展示。回放界面可拖动进度、播放/暂停、逐事件后退/前进并跳到开局或结算；终局显示役种、番符、宝牌/里宝牌、倍率和得分。在线和本地记录均由同一事件归约器驱动。

质量验证由 `tests/history.test.ts` 覆盖状态确定性、不可变帧、序号/版本错误、流局边界、状态恢复、振听、结算和隐私字段白名单；双浏览器 Playwright 测试从建房和选牌打到流局，再验证历史授权、事件导出及 UI 的逐步回放控制。

如需在本机执行 Playwright 且不碰默认 Wrangler 数据库，可先用 `npm run db:migrate:local -- --persist-to <临时目录>` 初始化独立数据库，再以相同的 `E2E_D1_PERSIST_PATH=<临时目录>` 启动 `npm run dev`，并设置 `E2E_BASE_URL` 执行 `npm run test:e2e:playwright`。
