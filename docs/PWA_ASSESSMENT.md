# PWA 与离线电脑对战评估

## 当前状态

当前版本没有 Web App Manifest、Service Worker、安装提示或离线缓存，因此目前不能作为已安装 PWA 使用。静态资源、页面与游戏逻辑由浏览器加载；登录、联机房间、账号会话和服务端对局状态依赖网络及 Cloudflare D1。

## 离线能力可行性

游客电脑对战适合离线化：牌墙生成、规则计分、电脑策略、牌桌与本机对局历史均在客户端运行。实现离线对局的主要工作是缓存应用壳、脚本、样式、字体和音效，并保证新版本缓存原子切换。浏览器首次至少需要联网加载一次应用。

以下能力离线时应明确显示不可用，而不是伪装成功：账号注册/登录、联机建房/加入、同步对局历史与服务器健康状态。规则百科与已缓存的静态内容可离线阅读；本机电脑对战记录可继续保存在本地。

## 建议实施顺序

1. 添加带版本号的 manifest、应用图标与安装元数据，先实现可安装性。
2. 为静态构建资源采用由构建系统生成的 precache 清单；避免手工缓存带哈希文件名的资源。
3. 增加离线兜底页和网络状态提示，明确在线功能不可用。
4. 采用网络优先的 API 请求策略，不缓存认证、房间快照或含隐藏手牌的响应。
5. 添加离线 E2E：首次安装缓存、断网启动、游客电脑对局、恢复联网升级缓存。

## 安全与维护边界

Service Worker 可持续控制同源请求，发布失误会造成旧客户端长时间滞留；需设定缓存版本、过期策略和回滚流程。禁止缓存认证 Cookie、用户私密数据、在线牌局快照及里宝牌等未公开信息。离线支持不等于可离线联机，联机和账号仍需服务端权威校验。

## 验收结论

PWA 安装与离线游客对战在当前架构下可行，但本次只完成评估，没有注册 Service Worker 或承诺离线可用。建议等页面模块、静态资源许可和发布缓存策略稳定后再实施，以免 Service Worker 将未完成版本长期留在用户设备上。
